# harbor-operator

A Kubernetes operator that manages [Harbor](https://github.com/goharbor/harbor)
users, groups, projects and robot accounts declaratively. Built with Operator SDK
and controller-runtime.

## Resources

All resources are namespaced and live in the `harbor.graphzc.io/v1alpha1` API group.
Every resource except `HarborConnection` references a `HarborConnection` in the
same namespace through `spec.harborConnectionRef`.

| Kind | Short name | Manages |
|------|------------|---------|
| `HarborConnection` | `hc` | Connection to a Harbor instance. The admin password comes from a Secret; an optional CA bundle Secret is supported. |
| `User` | `hu` | Harbor user accounts (requires database auth mode). |
| `Group` | `hg` | Harbor user groups (`HTTP`, `LDAP`, `OIDC`). |
| `Project` | `hp` | Projects, with visibility, storage quota, policies, CVE allowlist and user/group members. |
| `RobotAccount` | `hra` | System-level or project-level robot accounts and their permissions. |

Samples for each kind are in [config/samples](config/samples).

### Credentials

`User` and `RobotAccount` take their credential in one of two ways:

- **Referenced:** set `passwordSecretRef` (User) or `secretRef` (RobotAccount)
  to an existing Secret key. When the Secret changes, the new value is applied
  to Harbor.
- **Generated:** leave the reference out. The operator creates a Secret named
  `generatedSecret.name` (default `<resource>-harbor-credentials`) with the keys
  `username` and `password`. For users, the password is generated by the
  operator. For robots, the Secret holds the secret Harbor generated. The Secret
  is owned by the resource: if you delete the Secret, the operator recreates it.

Harbor requires passwords and robot secrets to be 8–128 characters with at
least one upper-case letter, one lower-case letter and one digit.

Status records only a bcrypt hash of the applied credential, never the
credential itself.

### Behavior

- **Adoption:** if a Harbor object with the same name already exists, the
  operator takes it over and makes it match the spec.
- **Drift correction:** every resource is re-checked every 10 minutes and
  whenever its `HarborConnection` or a referenced Secret changes.
- **Deletion:** `spec.deletionPolicy: Delete` (the default) removes the Harbor
  object when the resource is deleted; `Orphan` leaves it in place. If the
  `HarborConnection` or its Secret is already gone, the finalizer is removed
  without cleanup. Harbor refuses to delete projects that still contain
  repositories; the `Project` keeps its finalizer and reports a `DeleteError` until
  the repositories are removed.
- **Project members:** when `spec.members` is non-empty, it is authoritative.
  Members not in the list are removed, except the `HarborConnection` user. When
  the list is empty, membership is not managed.
- **Project policies:** a policy field that is not set is left as it is in Harbor.
- The `HarborConnection` user cannot be managed as a `User`, so the operator
  cannot change the password it connects with.
- Immutable fields (user `username`, project `name`, robot `name`/`level`, group
  `groupType`) are enforced by CEL validation.

Every resource reports a `Ready` condition; `kubectl get` shows it along with
the Harbor IDs.

## Quick start

```sh
kubectl create secret generic harbor-admin --from-literal=password='<admin password>'

kubectl apply -f - <<'EOF'
apiVersion: harbor.graphzc.io/v1alpha1
kind: HarborConnection
metadata:
  name: harbor
spec:
  url: https://harbor.example.com
  passwordSecretRef:
    name: harbor-admin
---
apiVersion: harbor.graphzc.io/v1alpha1
kind: Project
metadata:
  name: team-a
spec:
  harborConnectionRef:
    name: harbor
  name: team-a
  storageQuota: 50Gi
  policies:
    autoScan: true
---
apiVersion: harbor.graphzc.io/v1alpha1
kind: RobotAccount
metadata:
  name: team-a-ci
spec:
  harborConnectionRef:
    name: harbor
  name: ci
  level: project
  project: team-a
  permissions:
    - access:
        - { resource: repository, action: pull }
        - { resource: repository, action: push }
EOF

kubectl get hc,hp,hra
kubectl get secret team-a-ci-harbor-credentials -o jsonpath='{.data.password}' | base64 -d
```

## Development

Prerequisites: Go 1.27, Operator SDK 1.42, Docker, kubectl, Helm. kind is needed for the end-to-end tests.

```sh
make test        # unit + envtest controller tests (uses an in-memory fake Harbor)
make lint        # golangci-lint
make kind-e2e    # Helm chart + operator against a real Harbor in kind
make run         # run the controller locally against the current kubeconfig
```

Layout:

- [api/v1alpha1](api/v1alpha1): CRD types
- [internal/controller](internal/controller): reconcilers
- [internal/harbor](internal/harbor): minimal Harbor v2.0 REST client
- [internal/harbor/harbortest](internal/harbor/harbortest): in-memory fake Harbor used by the tests
- [charts/harbor-operator](charts/harbor-operator): Helm chart
- [hack/kind-e2e.sh](hack/kind-e2e.sh): end-to-end test script

After changing the API types or RBAC markers, run `make manifests generate helm-sync`.

## Deploy

With Helm (recommended):

```sh
make docker-build docker-push IMG=<registry>/harbor-operator:<tag>
helm install harbor-operator ./charts/harbor-operator \
  --namespace harbor-operator-system --create-namespace \
  --set image.repository=<registry>/harbor-operator --set image.tag=<tag>
```

With kustomize:

```sh
make install                              # install CRDs
make deploy IMG=<registry>/harbor-operator:<tag>
```

Uninstall with `helm uninstall harbor-operator -n harbor-operator-system`, or
`make undeploy` and `make uninstall`.

## CI and releases

GitHub Actions workflows in [.github/workflows](.github/workflows):

| Workflow | Runs on | Does |
|----------|---------|------|
| `Tests` | every push and PR | `make test` |
| `Lint` | every push and PR | golangci-lint, and checks that the Helm chart is in sync and lints |
| `E2E Tests` | every push and PR | the scaffolded kustomize deployment test in kind |
| `Build` | PRs, `main`, `v*.*.*` tags | builds the linux/amd64 + linux/arm64 image and smoke-tests it; pushes to GHCR except on PRs; on tags, also publishes the chart |

Images are pushed to `ghcr.io/graphzc/harbor-operator`:

- `main` and `sha-<short sha>` on every push to `main`.
- `<version>` and `<major>.<minor>` for a tag such as `v0.2.0`.

To release, push a semver tag:

```sh
git tag v0.2.0 && git push origin v0.2.0
```

The tag build pushes image `0.2.0` and chart `0.2.0`, whose default image is
that tag. Install it with:

```sh
helm install harbor-operator oci://ghcr.io/graphzc/charts/harbor-operator --version 0.2.0 \
  --namespace harbor-operator-system --create-namespace
```

New GHCR packages are private. To pull without credentials, make the
`harbor-operator` image and `charts/harbor-operator` chart packages public in
the package settings on GitHub. Otherwise, set `imagePullSecrets` in the chart.
